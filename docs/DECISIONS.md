## 1. 코드를 고칠 때 지켜야 하는 규약

이 규칙들은 특정 Task 가 만들어 냈지만 **지금도 코드 전체에 적용된다.** 새 요소를 넣을 때 확인한다.

| 규약 | 내용 | 출처 |
|------|------|------|
| **반응형 분기** | `useMediaQuery`(`@/hooks/useMediaQuery.ts`)를 쓴다. 폭 전환은 리렌더로 `useSyncExternalStore` 가 스냅샷을 다시 읽게 해야 한다 | R2 |
| **패널 마운트** | 플래너 세 패널은 **상시 마운트 + `hidden` 전환**. 조건부 렌더로 언마운트하면 뷰모드·카테고리·스크롤·지도 줌이 전멸한다 | R3 |
| **최소 폭 금지** | `main` 에 최소 폭이 없다. 새 요소는 좁은 폭에서 스스로 흘러야 한다 (`min-w-0`·`truncate`·`flex-wrap`) | R4 |
| **오버레이** | 새 오버레이를 만들면 `useBodyScrollLock(보이는가)` 을 **반드시** 부른다(카운팅이라 겹쳐도 안전). `viewport-fit=cover` 이므로 화면 가장자리 요소는 `env(safe-area-inset-*)` 를 스스로 피한다 | R5 |
| **모바일 지도** | 모바일에서 지도는 **기본 잠금**. 지도 위에 얹을 때는 `KakaoMap` 의 `interactive`(= `isDesktop \|\| unlocked`)와 컨트롤 스택(`controlsRef` = 마커 금지 구역)을 함께 본다 | R6, F8 ㉠ |
| **z 계층** | `index.css` 의 z 사다리 주석이 **정본** — 본문 0~10 · 헤더 30 · 드로어 40/50 · 토스트 50 · 모달 60/70. `.navbar` 가 스택 컨텍스트라 **헤더 안의 z 는 헤더 밖과 비교되지 않는다** | R7 |
| **터치 타깃** | 작은 컨트롤은 `.tap-44` 유틸리티(`index.css`). 전제 ①대상이 positioned 일 것 ②**바로 옆에 다른 탭 대상이 있으면 쓰지 않는다**(그 자리는 방향 지정 `before:` 로 바깥쪽만 넓히거나 실제 높이를 준다). 둥근 요소 옆에서는 **확장도 둥글게**(`before:rounded-full`) — 히트 판정이 `border-radius` 를 따르므로 사각 확장은 이웃의 중심을 가로챈다 | R8 |
| **토스트 위치** | 모바일에서 화면 **하단 중앙**(`sm:` 이상만 우상단). 하단 고정 요소는 `bottom:16px` 부터 최대 153px 띠와 겹칠 수 있다 | R9 |
| **홈 검색바** | 칸 껍데기는 `Index.tsx` 의 `FIELD_SHELL` 상수 **한 곳**. 모바일 테두리·48px 과 `lg:` 되돌리기가 한 쌍이다 | R10 |
| **벤더 CSS override** | 페이지 안에서 import 된 라이브러리 CSS 는 lazy 청크와 함께 `index.css` 보다 **늦게** 실린다 → 같은 특정도면 벤더가 이긴다. **특정도로 이겨야 한다** | R10 |
| **폰트** | `index.html <head>` 의 dynamic-subset `<link>` 로 들어온다. `index.css` 에는 `@font-face` 가 없다(`--font-sans` 만) | R11 |
| **hover** | Tailwind v4 가 이미 `hover:` 를 `@media (hover:hover)` 로 감싸 방출한다 → 터치 고착 방지용 래핑 **불필요**. 터치에 필요한 것은 `active:` 피드백 | R11 |
| **Tailwind 스캔** | 명령형 DOM(지도 마커 등)에 쓰는 클래스는 **빌드 CSS 에 emit 됐는지 확인**한다 — 스캐너가 놓치면 런타임에만 깨진다 | R8 |

## 2. 뒤집지 말 것 (또는 뒤집으려면 근거부터)

### 2-1. 지도에서 코스 편집은 **드래그가 아니라 마커 토글**이다 (F6)
드래그 3안을 전부 기각한 제약 4가지:
1. **마커가 React 트리 밖 DOM** — `KakaoMap` 이 `CustomOverlay` content 로 `document.createElement('button')` 를 만들고 `addEventListener` 로 연결(id 기준 수동 diff). dnd-kit 을 붙이려면 오버레이마다 `createPortal` 이 필요하고 결과 목록이 실측 **411곳**까지 나온다.
2. **모바일에선 지도와 코스 패널이 동시에 존재하지 않는다** — 탭 전환식이고 `ResultsPanel mobile` 은 어떤 `DndProvider` 에도 없다 → 모바일 DoD 충족 불가.
3. **포인터 경쟁** — 카카오맵이 컨테이너 드래그를 pan 으로 소비한다. 카카오 SDK 는 `setDraggable(false)` 이후에도 지도 내부 div 에 `touch-action:none` 을 **인라인으로** 박아 둔다.
4. **좌표 없는 장소는 마커 자체가 없다.**

### 2-2. 마커 겹침은 "위치 왜곡 < 겹침"으로 결정했다 (F7·F8 ㉡ — **미해결로 남김**)
POI 는 클러스터링하되 **코스 마커는 접지 않는다**(순번 배지·경로선 유지가 F5 DoD). 그 결과 한 Day 코스가 **5곳 이상 반경 300m** 에 몰리면 `spreadOverlaps` 가 빈 자리를 못 찾아 겹침이 남는다. 해소하려면 마커를 실제 위치에서 더 떼어 놓아야 하고, 그건 **위치 왜곡을 감수하는 설계 변경**이다 → 사용자 판단 사항으로 열어 뒀다.

### 2-3. 마커 토글의 44px 은 **기하학적으로 불가능**하다 (R8 — 32px 에서 멈춤)
배지(28px)와 토글(22px)의 **중심 거리가 12.7px**. 44px 상자는 배지를 거의 다 덮어 마커 탭(드로어 열기)을 통째로 먹는다. 바깥쪽으로만 넓혀 **32px**. 채우려면 마커 디자인 자체를 바꿔야 한다(토글을 배지에서 떼거나 선택된 마커에서만 크게 노출).
- ⚠️ 이 과정에서 **사각형 확장이 원형 배지의 중심을 가로채는 회귀**를 만들었다가 `before:rounded-full` 로 잡았다. §1 의 "둥근 요소 옆에서는 확장도 둥글게"가 여기서 나왔다.
- '마커 간 40px 이면 도달 보장' 기준은 R8 이후 **37.26px**(＜40, 여유 2.74px)로 재계산돼 여전히 유효하다.

### 2-4. 코스 카드의 인라인 트리거는 투명 확장을 쓰지 않는다 (R8)
시각(16px)·금액(24px) 두 줄의 중심 간격이 28px 뿐이라 44px 상자끼리 겹치고 위쪽 삭제 `X` 까지 덮어 **도달성이 오히려 나빠진다**(DOM 순서상 나중 요소가 이긴다) → 실제 높이 `min-h-11`. 카드가 98→**142px** 로 커진 것은 의도된 대가다.

### 2-5. 장소 삭제 `X` 는 히트박스를 키우지 않았다 (R8, 범위 밖)
**파괴적 동작**이라 확장하면 오탭 삭제가 늘어난다. 같은 이유로 `POICard` '코스 추가'(32px)·편집 패널 '완료/되돌리기'도 미해결로 남겼다.

### 2-6. 시각 역전은 자동 정렬하지 않는다 (F1)
같은 Day 에서 시각이 역전되면 toast 로만 안내한다. **코스 순서가 정본**이고 시각이 순서를 뒤집게 두지 않는다.

### 2-7. 이동시간은 좌표를 모르면 **표기를 생략**한다 (F3)
`travelTime.ts` 는 좌표가 없으면 `null` 을 돌려준다. 0분으로 보여 "바로 옆"으로 오해하게 두지 않는다.
계산 근거: 직선거리(`haversineKm`) → `DETOUR_FACTOR 1.3` 우회 보정 → 수단별 **실효** 속도(도보 4 · 대중교통 20 · 자차 40km/h, 대기·환승·시내 저속 포함한 문앞-문앞) → 5분 단위 라운딩·하한 5분.

### 2-8. 교통비 추정치의 숫자는 근거가 있다 (F2)
도보 0원 / 대중교통 **1인 1일 ₩9,000**(시외·시내버스 뭉친 값) / 자차 **1대(4인) 1일 ₩22,000**(1일 100km 유류비+통행료+주차). 하드코딩 `8500 × days × ceil(n/4)` 을 대체한 값이며 근거는 `utils/budget.ts` 주석에 있다. 사용자 입력(`transportOverride`)이 추정치를 이긴다(0원 유효, 음수는 0).

### 2-9. 찜 상태 표시는 **끝까지 서버 응답 기준**이다 (F4·F9)
localStorage 로 낙관적 상태를 만들지 않는다. 비로그인·탈퇴 사용자는 `liked:false`, 평점 행이 없으면 `stars:null`·`totalLiked:0` 이며 **에러가 아니다**.
- ⚠️ 백엔드 0.6.5 가 토글 응답 필드를 `likes` → **`totalLiked`** 로 개명했다. FE 가 따라가지 못해 **좋아요 수가 유실되던 실결함**이 있었다(F9 에서 수정). 목록 DTO 에는 `totalLiked` 가 **없다**(설계상 상세 전용).

### 2-10. 공개뷰는 `apiClient` 가 아니라 **순수 axios** 로 호출한다
공개뷰는 토큰 없이 200 이어야 하는데 인터셉터를 타면 비로그인 상태에서 재발급 경로로 샌다.

### 2-11. 코스 제목은 **서버 값이 정본**이다
생성 응답(GBC010)의 `title` 을 쓰고, FE 가 짓던 제목(`'{목적지} 여행 코스'`)은 폴백으로 격하했다. 서버의 `buildDefaultTitle` 은 항상 non-null(시군구 1개='경주 여행 코스' / 복수='경주 외 2곳 여행 코스' / 미선택='여행 코스'). 이 결정으로 생성 직후 제목이 목록·상세와 **같아진다**.

### 2-12. 좌표는 서버 `mapx`/`mapy` 가 1순위, 지오코딩은 **폴백**이다
백엔드 0.6.3 이 코스 상세·공개뷰에 좌표를 실어 준다(JSON number). 단 POI 캐시에 없는 `contentId` 는 `null` 이라(코스 1의 18곳 중 6곳) `kakaoGeocode` 폴백을 **제거하면 안 된다**. 생성(GBC010)은 DTO 가 달라 여전히 좌표가 없다.

### 2-13. `RootLayout.tsx` 는 의도된 플레이스홀더다 (A4)
삭제 금지. 향후 `Layout` 상위 공통 셸 자리이며 `RootLayout.tsx` 주석에 명시돼 있다.

## 3. 검증 방법 (이 프로젝트에서 통하는 것)

- **모바일 폭 실측** — 브라우저 창은 1440px 밑으로 리사이즈되지 않는다. **동일 출처 iframe 을 390×731 로 띄우면** 미디어쿼리가 실제 모바일 폭에서 평가되고, Vite dev 모듈 그래프로 스토어를 직접 주입할 수 있다. F5·F6·R8 이 이 방식으로 검증됐다.
- **순수 로직 검증** — `buildSchedulePayload`·`spreadOverlaps` 같은 순수 함수는 rolldown 번들 → node 실행으로 전수 케이스를 돌린다.
- **백엔드 대역** — 실 백엔드를 띄울 수 없을 때 `apiClient.defaults.adapter` 를 **런타임에만** 갈아 끼운다(코드 미변경).
- ⛔ **이 툴체인으로 만들 수 없는 것** — OS 수준의 실제 손가락 터치(pinch-zoom·롱프레스), `:active` 의 실제 눌림 렌더(CDP 합성 입력은 `:active` UA 상태를 켜지 않는다).
- ⚙️ **Java 부재** — 이 개발 환경에 `java`·`JAVA_HOME` 이 없어 에이전트가 `../back` 을 직접 띄울 수 없다. 사용자가 :8080 을 띄워 주면 라이브 검증이 된다.
